# Silent steals that are KNOWN, DISCLOSED and ACCEPTED for this release.
#
# One `name/spelling` per line. The gate fails on a SILENT row that is NOT listed here, and
# also fails on a line listed here that no longer reproduces — a baseline that can rot into
# a rubber stamp is worse than none.
#
# Every row below is in the CHANGELOG's "no diagnostic at the call site" section.
#
# The reason each is silent rather than reported is that `unused_must_use` does not fire on
# its discarded return. Measured, per name: `Result` is `#[must_use]` as a type
# (`peek_kind`); an `impl FnMut` return is covered by the lint's own rule for unused
# callables (`list_until`, `opt`); an `Option` is covered by NEITHER, and a plain adapter
# struct by neither. So the discriminator is the lint, not a `#[must_use]` attribute — the
# shorter statement was wrong for two of the three names it was meant to explain.
#
# ── 0.8.0's four: a bounded receiver ─────────────────────────────────────────────────────
#
# Each of the first four rides a bounded receiver — `ParseInput` / `TryParseInput` /
# `ParseAttempt`, whose blanket impls reject non-parser receivers — rather than every `Sized`
# type. That distinction is what decided the one removal 0.8.0 made: `PinOutputs::outputs`
# reached every `Sized` type and was cut; these do not.
into_option/discarded
labelled/later_pick_discarded
traced/later_pick_discarded
peek_then_head/later_pick_discarded

# ── `RecursionLimiter::unlimited` — a CONCRETE, PRE-EXISTING owner ───────────────────────
#
# This one does NOT ride a bounded receiver, and the paragraph above must not be read as
# covering it. `RecursionLimiter` is a plain public struct that has shipped since 0.7.3, so
# every consumer who has one already had somewhere to hang an `unlimited()` of their own —
# and no bound rejects them, because there is no bound. It is an inherent ASSOCIATED FN, so
# the collision is path resolution rather than a receiver walk.
#
# Reproduced, two-sided, base 60f27a3 (pre-#147) against this branch:
#
#     SILENT  unlimited/discarded    base=witness=1  head=witness=0
#
# Both sides compile, neither emits a diagnostic, and the two run different programs: the
# consumer's `unlimited()` on base, tokora's on head. `unlimited/used` is `loud` on the same
# template, so the discarded return is the whole of the difference — `RecursionLimiter` is a
# plain struct with no `#[must_use]`, and `unused_must_use` does not fire on it. Adding
# `#[must_use]` was considered and rejected: it would fire on tokora's own legitimate
# `let limiter = RecursionLimiter::unlimited();` only when the value is genuinely discarded,
# which is not this call site's shape, and it would not help a consumer who assigns the
# result — the silent case that matters and that this harness cannot generate at all.
#
# This is also the FIRST silent row in the `inherent_assoc_fn` category. The README records
# that the category's `loud` verdicts are arity verdicts about the probe rather than
# statements about the name, and that a `silent` row there "would be news". It is news, and
# it is recorded rather than argued away.
#
# WHY IT IS DISCLOSED HERE AND NOT ON THE RELEASE THAT ADDED THE NAME: `unlimited` is new in
# 0.8.0 (#147), which shipped before the collision probe had a template for its owner — the
# job reported FATAL, an INCOMPLETE verdict, and the row was never constructed. #148's Stage A
# added the template and reproduced the finding. It has to be disclosed on THIS branch: the
# inventory is a two-sided delta, so once this merges the name is no longer new, the row falls
# out of every future plan, and the harness can never re-litigate it (README, "Staleness is
# checked only for rows this run planned").
#
# THE LINE ITSELF IS NOW REMOVED, and the paragraph above is kept anyway — the finding is
# permanent (it is in the CHANGELOG), the reconciliation LINE is not. `run.sh` reconciles by
# the bare `name/spelling` label, with no owner in it, and the input-token-budget branch mints
# a SECOND, unrelated inherent associated fn also spelled `unlimited` — `TokenBudget::unlimited`
# (see the `new-owner` rows this branch's own run adds below `token_budget`'s no_collision.txt
# entry). `surface_diff.py` recorded that name against the new owner, `RecursionLimiter` did not
# change, and `RecursionLimiter::unlimited` is not part of this diff's added-name set at all —
# so THIS run's `unlimited/discarded` probe is against `TokenBudget`, not `RecursionLimiter`,
# and it lands `new-owner`, not `SILENT`. Leaving the line in place would make every run from
# here on report it STALE, forever, over a row it was never testing. Removing it does not
# revisit whether `RecursionLimiter::unlimited/discarded` still steals silently — a two-sided
# delta harness cannot re-litigate a name that is no longer new, on this owner or any other,
# which is the same rule the paragraph above already states for why this had to be disclosed at
# #148's time and not later. If `RecursionLimiter` itself is ever touched again by a diff that
# makes `unlimited` new there a second time, that run reconstructs the finding on its own
# evidence rather than trusting this stale line.

# ── `ParseState`'s four ZERO-ARGUMENT forwarders — a PRE-EXISTING callback view ───────────
#
# `ParseState` is the view a state-carrying callback (`map_with`, `and_then_with`,
# `validate_with`, `fold`) is handed, and it has shipped since 0.7.3. What it had NOT shipped
# is a single inherent item: the callback reached the emitter through `state.emitter()`, and
# #168 replaced that door with thirteen forwarding methods under the emitter's own names. So
# every consumer who wrote `fn exit_label(&mut self)` on `ParseState` to shorten
# `state.emitter().exit_label()` — the most natural helper 0.7.3 offered — now competes with a
# tokora method of the same name on the same receiver.
#
# Reproduced, two-sided, base 7b289bc against this branch, on rustc 1.97.1:
#
#     SILENT  cst_mark/discarded              base=witness=1  head=witness=0
#     SILENT  emitter_bound_source/discarded  base=witness=1  head=witness=0
#     SILENT  emitter_ref/discarded           base=witness=1  head=witness=0
#     SILENT  exit_label/discarded            base=witness=1  head=witness=0
#
# Both sides compile, neither emits a diagnostic, and the two run different programs.
#
# WHY THESE FOUR AND NOT THE OTHER NINE: they are the whole of the zero-argument set. The
# probe's consumer takes no arguments, so for the nine forwarders that take one or two the
# head side fails on the PROBE's own arity (E0061) and the row is filed `loud` — a verdict
# about the probe, not about the name (README, "What this harness does NOT test"). Read this
# as "the four the harness could reach are silent", never as "the other nine are safe".
#
# WHY `discarded` AND NOT `used`: all four `used` rows are `loud` on the same template, by
# E0308 against the consumer's `-> u8`. The discarded return is the whole of the difference,
# and none of the four returns something `unused_must_use` fires on — `()` (`exit_label`), a
# plain `EventMark` (`cst_mark`), an `Option` (`emitter_bound_source`, and `Option` is not
# `#[must_use]` as a type), a shared reference (`emitter_ref`). Same discriminator as the four
# 0.8.0 rows above: the lint, not a `#[must_use]` attribute.
#
# NOT a bounded receiver, and the 0.8.0 paragraph above must not be read as covering these.
# `ParseState` is a concrete public type; there is no blanket impl to reject anybody. The
# subject is reached rather than constructed — `ParseState::new` is `pub(super)` — so the
# probe drives a real parse and takes the state from a `map_with` callback, which hands it
# BY VALUE. That is what makes the row a measurement: from a by-value receiver tokora's
# `&self` items are found at the `&T` pick and its `&mut self` items at the `&mut T` pick,
# where an inherent item beats the consumer's trait item.
cst_mark/discarded
emitter_bound_source/discarded
emitter_ref/discarded
exit_label/discarded

# ── `Cst::resource_trips` — the first row added to `Cst` AFTER `Cst` shipped ──────────────
#
# `Cst` is the handle both lossless drivers return, and `resource_trips` is the first inherent
# item added to it since it shipped. So unlike the seven items it arrived with, this one has a
# real before-state: a consumer holding a `Cst` already had somewhere to hang the name.
#
# Reproduced, two-sided, base 543ce6d against this branch, on rustc 1.99.0-nightly:
#
#     loud    resource_trips/used         base=witness=1  head=no-compile
#     SILENT  resource_trips/discarded    base=witness=1  head=witness=0
#
# Both sides compile on the discarded row, neither emits a diagnostic, and the two run different
# programs. `used` is `loud` by E0308 against the consumer's `-> u8`, so the discarded return is
# the whole of the difference — the method returns a plain `usize`, which carries no `#[must_use]`
# and which `unused_must_use` does not fire on. Same discriminator as every row above: the lint,
# not an attribute.
#
# NOT a bounded receiver. `Cst<'inp, L, E>` is a concrete public struct; there is no blanket impl
# to reject anybody, exactly as for `RecursionLimiter::unlimited` and `ParseState`'s four.
#
# `#[must_use]` was considered and rejected for the reason it was there: it does not reach a
# consumer who *assigns* the result — the silent case that matters and that this harness cannot
# generate — while firing on legitimate discards of tokora's own.
#
# ADDING THIS ROW ALSO CHANGED THE TEMPLATE, which is worth recording because the change is not
# specific to this name. `gen_probe.py`'s `Cst` subject bound the handle immutably, and the
# generated consumer item always takes `&mut self`, so on a base side where the consumer's item is
# the ONLY candidate the probe was E0596 and never compiled. For an owner the same diff introduces
# that is invisible — the base side is expected not to compile — so it survived until the first
# row with a before-state. The binding is now `mut` (`drive()` already carries
# `#[allow(unused_mut)]`, so the reason it was immutable had already stopped applying), and the
# `used` binding for this row is the CONSUMER's `u8` rather than the item's real `usize`, which is
# the shape the table's header prescribes for a pre-existing owner.
resource_trips/discarded

# ── `Errors`' three replacement methods — a PRE-EXISTING struct that had NO inherent item ─
#
# `Errors` has shipped since 0.7.3 with `DerefMut` onto its container and no inherent removal
# or element-mutation door of its own, so `errors.pop()`, `errors.clear()` and
# `errors.iter_mut()` all reached the container's API through the deref — or, for a consumer
# who wanted a different shape, an extension trait of their own. #247 removes `DerefMut` (it
# was also the insertion bypass that defeated `overflowed()`) and replaces those three with
# inherent methods, so every such consumer now competes with a tokora method of the same name
# on the same receiver, and an inherent item wins the pick.
#
# Reproduced, two-sided, base 40694dc against this branch, on rustc 1.99.0-nightly:
#
#     loud    clear/used          base=witness=1  head=no-compile
#     SILENT  clear/discarded     base=witness=1  head=witness=0
#     loud    iter_mut/used       base=witness=1  head=no-compile
#     SILENT  iter_mut/discarded  base=witness=1  head=witness=0
#     loud    pop/used            base=witness=1  head=no-compile
#     SILENT  pop/discarded       base=witness=1  head=witness=0
#
# Both sides compile on the discarded rows, neither emits a diagnostic, and the two run
# different programs. Every `used` row is `loud` by E0308 against the consumer's `-> u8`, so
# the discarded return is the whole of the difference — the same discriminator as every row
# above, and measured per name rather than assumed: `clear` returns `()`; `pop` returns an
# `Option`, which is not `#[must_use]` as a type; and `iter_mut` returns the container's own
# `IterMut`, which — despite "iterators are lazy" being the canonical `#[must_use]` — the lint
# did not fire on here. That third one is why the set is measured: it is the row a rule of
# thumb would have predicted `warned`.
#
# NOT a bounded receiver. `Errors<E, C>` is a concrete public struct; there is no blanket impl
# to reject anybody, exactly as for `RecursionLimiter::unlimited`, `ParseState`'s four and
# `Cst::resource_trips`.
#
# THE DEREF DOES NOT ENTER IT, and that is worth stating because the base side still had one:
# a deref step is walked only after every pick on `Errors` itself has failed, and the
# consumer's item is found at the `&mut Errors` pick. So what the base side runs is the
# consumer's item, not `VecDeque`'s — the before-state is a real one either way.
clear/discarded
iter_mut/discarded
pop/discarded
